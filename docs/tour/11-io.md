# Input and output

## The library words

`print` and `println` write a string to the console. `read-line` reads
one: it leaves the line, without its newline, and a flag that is 0 once
the input has ended.

```wack
: count-lines ( -- i32 )
  0 :> n!
  [ read-line nip ] [ n 1 i32.add n! ] while
  n ;

: plural ( i32 -- str )  1 i32.eq [ " line" ] [ " lines" ] if ;

test plural : 1 plural -> " line"
test count-lines : count-lines -> 0

: main ( -- )
  "counting lines" println
  count-lines :> n
  n i32.to-str print  n plural println ;
```

`wack test` does not run `main`, and gives each test an empty console, so
`count-lines` counts 0 there. Run for real, the program reads what it is
given: `printf 'a\nb\n' | wack run lines.wack` prints

```
counting lines
2 lines
```

More words: `read-file ( str -- str i32 )` takes a path and leaves
the contents and a status, 0 for success; `write-file ( str str -- i32 )`
takes the contents and a path; `copy ( str str -- i32 )` takes the path
to read and the path to write; `ls ( str -- i32 )` prints a directory, one
entry per line; and `now ( -- i64 )` is the time in nanoseconds since the
Unix epoch.

## Everything is a path

Those words are written in Whackford, on top of four host words: `host.open`,
`host.read`, `host.write` and `host.close`. `host.open` takes a path and a
mode (`host.OREAD`, `host.OWRITE`, `host.OAPPEND` or `host.ORDWR`) and leaves a
handle. Any negative result from the four is an error: -1 is not found, -3
not supported.

What a program can reach is a namespace of paths:

| Path | What it is |
|---|---|
| `/dev/cons` | the console |
| `/dev/time` | the clock |
| `/file/<path>` | the host file `/<path>` |
| `/mnt/<name>/...` | a directory given with `--mount name=DIR` |
| `/net/http/<host>/<path>` | an HTTP request |

```wack
: in-etc ( str -- str )  "/file/etc/" swap str.concat ;
test in-etc : "hostname" in-etc -> "/file/etc/hostname"

: main ( -- )
  "hostname" in-etc read-file :> status :> text
  status 0 i32.eq [ text print ] [ "could not read it" println ] if ;
```

The host decides what is in the namespace: `wack run --no-file` leaves
out `/file` and `--no-net` leaves out `/net`, and those paths then give -3.

## HTTP

Reading a `/net/http` path sends a GET and gives the response body:

```wack fragment
: main ( -- )
  "/net/http/example.com/" read-file :> status :> body
  status 0 i32.eq [ body print ] [ "request failed" println ] if ;
```

To send headers or a body, `host.open` the path and write header lines, an
empty line and the body; the request goes out at the first read.

## In the browser

The browser REPL has a smaller namespace. Console output goes to the page,
but console reads give end of input at once. There is no `/file` and there
are no mounts. `/net/http` goes through `fetch`, so a server on another
origin must allow CORS.

In their place is `/local/<name>`: files kept in the browser's local
storage, which last from one visit to the next. Copy something there once
and read it as often as you like:

```wack-repl
"/net/https/example.com/" "/local/page" copy
"/local" ls
"/local/page" read-file
```
