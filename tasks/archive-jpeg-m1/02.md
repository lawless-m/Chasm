TASK: in jpeg/bits.wack (which already has `struct bitreader  data pos buf nbits marker exhausted`, `bits.open ( bytes i32 -- bitreader )` and `bits.fill ( bitreader -- )`, the latter loading bytes while nbits <= 24 and stopping at a marker or the end of data) add the bit-level words, contract first. Callers ask for n in 0..16 bits (a Huffman code is at most 16 bits; extra bits at most 15): state that contract in a comment.
- `bits.ensure ( bitreader i32 -- )`: make at least n bits available. If nbits < n: bits.fill; if nbits is still < n (a marker or the end of the data is in the way), set exhausted to 1 and pad with zero bits exactly as libjpeg's jpeg_fill_bit_buffer does at no_more_bytes: buf = buf << (25 - nbits), nbits = 25. This is the hard end-of-data state: the bits handed out from here on are zeros and the flag says so; the caller (the scan layer, M2) tests `bitreader.exhausted` and refuses in strict mode. Reading past the end is never a trap and never a refusal here. pos and marker are unchanged by the padding.
- `bits.peek ( bitreader i32 -- i32 )`: ensure n, then the next n bits without consuming them: (buf >> (nbits - n)) & ((1 << n) - 1). n = 0 gives 0.
- `bits.skip ( bitreader i32 -- )`: ensure n, then nbits -= n.
- `bits.get ( bitreader i32 -- i32 )`: the next n bits, consumed (peek then skip, or the same arithmetic inline).
