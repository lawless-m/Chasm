TASK: create jpeg/huffman.wack with the table builder. M0's markers.dht has located each table: `jpeg.huff-at` (8 entries, index tc*4+th) holds the offset in the input of a table's 16 counts, the symbols following right after them; it has checked the total of the counts <= 256, that the symbols fit in the segment, and the Kraft sum <= 65536. Struct: `struct hufftable  lookup: array i32  maxcode: array i32  valoffset: array i32  symbols: array i32  nsymbols: i32`. lookup has 256 entries indexed by the next 8 bits: (code length << 8) | symbol for a code of at most 8 bits, else 9 << 8 = 2304 meaning too long (libjpeg's (HUFF_LOOKAHEAD + 1) << HUFF_LOOKAHEAD). maxcode and valoffset have 18 entries indexed by code length 1..16 (index 0 unused): maxcode[l] is the largest code of length l, or -1 when there are none, with the sentinel maxcode[17] = 0xFFFFF (1048575) and valoffset[17] = 0; valoffset[l] = (index in symbols of the first symbol of length l) - (the smallest code of length l), so a code of length l maps to symbols[code + valoffset[l]]. symbols has 256 entries (the first nsymbols used).

`huffman.build ( bytes i32 i32 -- hufftable )`: the input, the offset of the 16 counts, and is-dc (1 for a DC table, 0 for AC). Steps, with refusals (every message containing the word Huffman, which a later corpus task relies on): (1) read the 16 counts with markers.u8; total = their sum; total > 256 is `BAD_TABLE "Huffman symbol count" total refusal-n trap` (checked before any symbol is read). (2) Allocate the four arrays (bind inputs to locals first). (3) Read the total symbols into symbols[0..total) via markers.u8 from offset + 16; nsymbols = total. (4) Figure C.2 with libjpeg's check: code = 0; for l = 1..16: the counts[l] codes of length l are code, code+1, ..., so mincode_l = code, maxcode_l = code + counts[l] - 1 (no scratch array of codes is needed: codes are consecutive within a length); code += counts[l]; then if code >= 1 << l refuse `BAD_TABLE "Huffman table with an all-ones code, length" l refusal-n trap` (libjpeg's JERR_BAD_HUFF_TABLE: no code may be all ones, so a table whose Kraft sum is exactly 1, which markers.dht allowed, is refused here, matching libjpeg); code = code << 1. Fill maxcode[l] and valoffset[l] for each length with codes (valoffset[l] = p - mincode_l where p is the running symbol index), maxcode[l] = -1 otherwise; set maxcode[17] = 0xFFFFF, valoffset[17] = 0. (5) Lookahead: fill lookup with 2304, then for l = 1..8 and each code of length l at symbol index p: for every 8-bit value starting with that code (code << (8 - l), 1 << (8 - l) consecutive entries) set lookup[v] = (l << 8) | symbols[p]. (6) If is-dc, every symbol must be <= 15 (DC categories up to 15 cover 12-bit; libjpeg's lossy rule), else `BAD_TABLE "Huffman DC symbol over 15" sym refusal-n trap`. All loops are bounded by 16, 256 or the counts.
