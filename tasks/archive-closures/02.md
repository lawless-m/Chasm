Design point (M10 closures, agreed): a quotation value (a `[ ... ]` not under a combinator) may carry an annotation written directly after `[`: `[ ( i32 -- i32 ) 1 i32.add ]`. Quotations under combinators (`if`, `when`, `unless`, `while`, `until`, `times`, `each`, `map`, `filter`, `fold`, `match` arms) stay inlined syntax and may not carry one. This is the only new syntax of the milestone.

Do, in crates/core/src:
- ast.rs: change `NodeKind::Quote(Body)` to carry an optional effect, e.g. `Quote { body: Body, effect: Option<Effect> }`.
- parser.rs `body_inner` (the `text == "["` arm, ~line 621): after `[`, if the next token is `(`, parse it with the existing `effect()` helper (which requires `--`), then the body up to `]`. A `(`-group without `--` there is still a stack assertion as today (keep `[ ( i32 ) ... ]` meaning an assertion). Update the places that pop `NodeKind::Quote` for combinators (`combinator_arity` loop, ~line 679) and for `match` arms (~line 653): if the popped quotation has `Some(effect)`, return `E_SYNTAX` with a message like "a quotation under `times` is inlined and takes no effect; write the annotation only on a quotation value".
- infer.rs `children()`, check.rs `NodeKind::Quote` arm (~line 1774) and any other `NodeKind::Quote` match (grep `NodeKind::Quote` across crates/) to the new shape. In check.rs, when the annotation is present compile the quote body with `Mode::Declared(&effect)` instead of `Mode::Derived` (the existing `compile_body` call); with none, keep `Mode::Derived` for now (inference is the next task). Call `ctx.check_types` on the annotation's types as `Assert` does.
