Repo: /home/matt/Git/Whackford. Design point (M10 closures, agreed): a quotation value that names an immutable local (`:> k`) of an enclosing word captures it implicitly, by value, at creation. Each capturing quotation gets its own env type `$env<q> = sub $closure (struct (field i32) (field <captured>...))`, one `struct.new` per closure creation; the quote's function casts param 0 to its env subtype (`ref.cast`) to read captures. Capturing a mutable local (`:> acc!`), including assigning `acc!` inside the quotation, remains an error under the EXISTING code `E_CAPTURE` (codes are a contract: keep the code, change the message to say mutable locals cannot be captured and advise boxing shared mutable state in a struct). Locals are still not visible to tests.

Do, in crates/core/src/check.rs:
- Replace `compile_body`'s `outer_locals: &[String]` ("used only to report captures") with a list of visible outer locals carrying name, type and mutability (e.g. `struct Capture { name, ty, mutable }`), built at the `NodeKind::Quote` arm from `self.locals` plus the walker's own captures (so nested quotation values capture through the enclosing quotation). In `Walker::name_ref`, after own locals: an immutable outer local → emit the env read (`local.get 0; ref.cast env; struct.get env field`, or cast once into a local in a prologue) and record it as used; a mutable one, or `name!` of one → `E_CAPTURE` with the new message. `undefined()` keeps reporting E_UNDEFINED otherwise.
- The set of used captures is determined by the quote body's checking pass and is identical in the emitting pass (same input); the env type is `register_rec` of one final `Member::Struct { fields: [I32, lowered captured types...], supertype: Some(closure_type) }` (no array member), registered in the emitting pass; the quote word records its env type index so `Walker::run` for that word lowers param 0 as `ref null $env<q>` or casts from `$closure` (either is fine as long as `call` passes a `(ref null $closure)` and validation passes). Creation emits `i32.const quote_id; <local.get of each captured local's idx>; struct.new env`.
- Inlined blocks (`times`, `each`, ...) inside a quotation value read captures the same way, since they share the walker.

Add tests to crates/core/tests/compile.rs: `: adder ( i32 -- [ i32 -- i32 ] ) :> k [ k i32.add ] ;` with `test adder : 3 adder 4 swap call -> 7`; `: scale ( vec i32 i32 -- ) :> k [ k i32.mul drop ] vec.each ;`-style use of a prelude word taking a function value with a captured local; nested `:> k [ [ k ] ] ;` giving `[ -- [ -- i32 ] ]`; `:> n! [ n ]` and `:> n! [ 1 n! ]` are `E_CAPTURE`; `test adder : 1 adder call -> 1` style misuse is a type error not a capture error. Pin that a struct can be the box: `struct cell  v: i32` then `[ c cell.v 1 i32.add c cell.v! ]` capturing immutable `c` works.
