Repo: /home/matt/Git/Chasm. The browser REPL (web/) needs `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (web/README.md explains; web/serve.py sends them). GitHub Pages cannot send headers, so write an in-repo service worker in the style of the MIT coi-serviceworker (write it yourself; fetch no third-party code):

1. `web/coi-sw.js`: a classic service worker. On `install` call `skipWaiting()`; on `activate` call `clients.claim()`. On `fetch`: ignore requests whose `cache` is `only-if-cached` and `mode` is not `same-origin`; otherwise respond with `fetch(request)` re-wrapped in a new Response with the same status and body and a copy of the headers where `Cross-Origin-Opener-Policy` is set to `same-origin` and `Cross-Origin-Embedder-Policy` to `require-corp` ONLY IF the response does not already carry that header (so a server that sends its own, including `credentialless` for the bridge page, is left alone); responses with status 0 (opaque) are passed through untouched.
2. `web/coi.js`: a classic (non-module) page script, around 25 lines. If `window.crossOriginIsolated` is true, or `navigator.serviceWorker` is undefined, do nothing (this is the no-op path for the intranet deploy and web/serve.py). Otherwise register `coi-sw.js` (same directory, default scope); if the registration becomes active and `navigator.serviceWorker.controller` is null (first visit, the page is not yet controlled) reload once; also reload on `controllerchange`. Guard against reload loops: do not reload if `sessionStorage` has a `coi-reloaded` flag already set for this page load sequence (set it just before reloading; clear it when the page loads isolated). Log one short `console.warn` if the page is still not isolated after a reload, and give up.
3. `web/index.html`: add `<script src="coi.js"></script>` before the `main.js` module script. Nothing else in the page changes.
4. `site/headless.sh`: modelled on `web/test/headless.sh` (read it), but it serves a directory WITHOUT the headers using `python3 -m http.server PORT --bind 127.0.0.1 --directory DIR` (port 8766, debugging port 9334, so it can coexist with the other script), and it always opens `PAGE%23code=<base64url>` where the code is `: sq ( i32 -- i32 ) dup i32.mul ;\ntest sq : 3 sq -> 9\n` encoded with `base64 -w0 | tr '+/' '-_' | tr -d '='`, then waits for the console marker `link ok` (printed by main.js when the fragment's chunks all ran). Usage: `sh site/headless.sh [DIR] [PAGE] [browser]`, defaults `tmp/site` and `repl/index.html`, browser `vivaldi`. Profile and logs under `tmp/headless-site/`, removed at the end; prints the marker line and exits 0 only on `link ok`. Note in its header comment that `%23` is needed because curl drops a literal `#`.
5. `web/README.md`: in "Running it", one short paragraph: `coi.js` registers `coi-sw.js` on a server that does not send the two headers and reloads once; it does nothing when the page is already cross-origin isolated.
