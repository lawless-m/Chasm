Context: djpeg applies block smoothing by default to progressive files whose coefficients are not fully known when output is produced; no flag turns it off, and it changes the output of every DC-only or unrefined progressive file (a 16x8 DC-only greyscale file decodes to `00 00 00 04 16 2F 49 5B 77 89 A3 BC CE DA E2 E6` per row where the plain IDCT would give 0A x8 C8 x8). In djpeg all scans are consumed before output, so coef_bits holds each coefficient's final Al (or -1 if never scanned); since strict mode refuses scans that end early, libjpeg's `output_iMCU_row > last_good_iMCU_row` case never happens and only the current coef_bits are used. smoothing_ok (progressive_mode is the caller's check): for every component, the latched quant table's entries at natural positions 0, 1, 8, 16, 9, 2, 3, 10, 17, 24 must be nonzero and coef_bits[ci][0] >= 0; smoothing is useful if any coef_bits[ci][k], k 1..9, is nonzero (-1 or > 0). decompress_smooth_data per block: with Al = coef_bits[k] for zigzag k 1..9 and change_dc = (coef_bits[1..9] all -1), each of the first AC coefficients that is still zero in the block and has Al != 0 gets an estimate from the DC values of the 5x5 neighbourhood: num = Q00 * (kernel sum, an int; the product in i64), pred = ((Qk << 7) + |num|) / (Qk << 8) with num's sign restored, clamped to (1 << Al) - 1 when Al > 0 (never when Al is -1); AC01 (natural 1) uses coef_bits[1], AC10 (8) [2], AC20 (16) [3], AC11 (9) [4], AC02 (2) [5] always, with different kernels for change_dc and not; AC03 (3) [6], AC12 (10) [7], AC21 (17) [8], AC30 (24) [9] and the DC itself (replaced by its own 25-tap estimate, no clamp) only when change_dc. The 25 DCs DC01..DC25 are rows -2..+2 by columns -2..+2 around the block; libjpeg's sliding registers with the first-column and last-column special cases are exactly equivalent to clamping the column to [0, width_in_blocks - 1] (say so in the comment); rows follow libjpeg's rule with its quirk: with ibr = output_iMCU_row * block_rows + block_row and ibrs = block_rows * total_iMCU_rows (block_rows is v_samp_factor except in the last iMCU row, where it is height_in_blocks mod v, or v when that is 0), prev = row - 1 if ibr > 0 else row; prev_prev = row - 2 if ibr > 1 else prev; next = row + 1 if ibr < ibrs - 1 else row; next_next = row + 2 if ibr < ibrs - 2 else next, where row is the absolute block row in the padded store (so for the last iMCU row the rows fetched are the real neighbours while the conditions use the reduced numbering). DC values are the 16-bit JCOEFs (`coeffs.get`). The quant tables are the components' latched tables in natural order laid out ci*64, as rows.wack's `quants`.
