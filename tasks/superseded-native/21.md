M11 at `wack repl`: the session's store is created with the async engine and the same `wack.spawn` global and async `ring_enter` as the runner; the `Scheduler` lives in the store data for the whole session. Each step: run the step's tests, then the line, each as process 0 named by the test's word or `[line N]`, driving the scheduler exactly as the runner does; the step is settled when process 0 has returned and nothing is ready (parked processes stay and are resumed in later steps when a line or test wakes them: a channel kept on the stack or in a word lets a later step send to a receiver spawned earlier); if process 0 is parked and `scheduler.blocked()` reports no runnable process and no I/O pending, the line is cancelled (kill pid 0, its fiber dropped) and reported as its trap with that message (stack restored as for any trap), while other parked processes remain; a trap in a spawned process kills only it and is reported in a new `Outcome.process_traps: Vec<RunError>` (each with `process: Some(pid)`). Timing fields stay. `crates/cli/src/main.rs` `repl_report`: render each process trap as `trap in \`word\` (process N): message` and add `results.process_traps` (array of `{message, word, process}`) to the JSON report.
