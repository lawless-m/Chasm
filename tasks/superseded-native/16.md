Read FUTURE.md section 9 and `crates/core/src/layout.rs` (OP_SPAWN=5, OP_CHAN_MAKE=6, OP_CHAN_SENDER=7, OP_CHAN_SEND=8, OP_CHAN_RECV=9, OP_CHAN_CLOSE=10, OP_ALT=11, E_CLOSED=-7, E_BAD_HANDLE=-5, E_MALFORMED=-6, E_NOT_FOUND=-1, E_PERMISSION=-2). Add `crates/runtime/src/proc.rs` (declare `pub mod proc;` in `crates/runtime/src/lib.rs`, available without the `native` feature: it holds no wasmtime types) implementing the M11 scheduler as a pure state machine, the Rust twin of `web/proc.js`: `pub type Pid = u32;` `pub struct Scheduler` with `new()` (pid 0 = the main process), `spawn(&mut self, slot: u32) -> Pid` (pid N in spawn order, state ready; the host keeps the closure beside it), `submit(&mut self, pid, op: i32, a0: i32, a1: i32, a2: i32, mem: &[u8]) -> Submit` where `pub enum Submit { Done(i32), Park }`, `next(&mut self) -> Option<(Pid, i32)>` (the next ready process and the result it resumes with, FIFO), `exit(&mut self, pid)`, `kill(&mut self, pid) -> bool`, `io_start(pid)`/`io_done(pid)`, `live(&self) -> Vec<Pid>`, `blocked(&self, name: &dyn Fn(Pid) -> String) -> Option<String>`. Channel rules (identical to the browser): SEND pushes the pid onto the channel's `queued` FIFO; if a receiver is parked, wake it (result 1, or `2*i+1` for an alt arm i) and pop the front of `queued` waking that sender with 0; else the sender parks; closed is `E_CLOSED` at once. RECV: a queued value → pop its sender (wake with 0) and `Done(1)`; closed → `Done(0)`; else park. CLOSE: senders -1; below zero `E_CLOSED`; at zero closed and every parked receiver wakes with 0. SENDER: +1. ALT: ids from `mem` at a0 (little-endian i32, count a1); the lowest ready arm completes at once with `2*i+v`; else park as a receiver of every id with its arm index, removed from the others when woken. Unknown ids `E_BAD_HANDLE`. `kill` removes the pid from every wait list (a killed sender's `queued` entry stays so its value is still delivered, never woken). `blocked` returns `None` while any process is ready or waiting on I/O, else `Some("all processes blocked: <name> waits to receive on chan 1; <name> waits to send on chan 1; <name> waits on chan 1, chan 2 (alt)")` in pid order; the host names pid 0 (`main`, a test's word, `[line N]`) and others are `process N`. Also the `/prog` namespace on the scheduler (`prog_open(path, mode) -> i32`, `prog_read(handle, buf) -> i32`, `prog_write(handle, bytes) -> i32`, `prog_close(handle) -> i32`, handles from 3 in their own map): reading `/prog` gives directory records (u32 name length, name, u64 size 0, u8 is-dir 1) of live pids in order; `/prog/<pid>/ctl` opened for writing; writing `kill` (optional trailing newline) kills; other text `E_MALFORMED`; unknown pid `E_NOT_FOUND`; reading ctl `E_PERMISSION`; other paths `E_NOT_FOUND`. Unit tests in the module (`#[cfg(test)]`) mirror `web/test/proc.mjs`: send/recv parking both ways, two senders with close counting, over-close, send after close, recv on closed-and-drained, alt lowest-ready and wake from either, kill of a parked receiver, the `blocked` message text, and `/prog` records and ctl.
