Repo: /home/matt/Git/Whackford. The compiler's unwind/rewind transform treats a ring submission as a suspension point when the literal opcode directly before `ring.submit` is a parking opcode. Three places list the parking opcodes as `OP_CHAN_SEND | OP_CHAN_RECV | OP_ALT` (prefixed `layout::` or `L::`): crates/core/src/check.rs in `fn site_flags` (around line 2492) and in the `"ring.submit"` arm of the special-word emission (around line 3838, `Some(&I::I32Const(op)) if self.transformed && matches!(op, ...)`), and crates/core/src/program.rs in `fn suspendable` (the `parks` closure, around line 225). Add `| OP_SLEEP` (with the same prefix) to each of the three. Do not change `process_ops` in check.rs: `op >= OP_SPAWN` already counts 12 as a process op, so a program using only `time.sleep` is a process program and `build --wasi` refuses it. In program.rs update the E_WASI_UNSUPPORTED message text from "spawns, or sends or receives on a channel" to "spawns, sleeps, or sends or receives on a channel" (the code stays E_WASI_UNSUPPORTED; diagnostic codes are a contract). In crates/cli/src/main.rs (around line 941) change the build note "service ring opcodes 5 to 11" to "service ring opcodes 5 to 12".
