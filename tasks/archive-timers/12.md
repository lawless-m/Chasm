Add two table rows after `chan.close`: `time.sleep` | `( i32 -- )` | Wait that many milliseconds (negative: none); other processes run meanwhile. `time.after` | `( T i32 -- chan T )` | Given a value and a count, a channel that receives the value once, that many milliseconds from now, and is then closed; an `alt` arm on it is a timeout. Add a short paragraph: `time.after` is written in the prelude on `time.sleep` (spawn, sleep, send, close); sends rendezvous, so when nobody receives the timer's process stays parked on its send (dropped by `run`/`test` when process 0 returns, kept and listed in `/prog` by a REPL); a sleeping process is never blocked, so the all-processes-blocked trap fires only when nothing is ready and nothing sleeps; `run`, a test and a REPL step end when process 0 has returned and nothing is ready, so sleeping processes are then dropped (`run`, `test`) or stay for later steps (REPL). Decisions taken in M14" in the same numbered-bold style recording: 1. `time.sleep` is a prelude word on ring opcode `OP_SLEEP` (12), a parking op like the channel ops, so it is a switch point and a program using it is a process program (`build --wasi` refuses it). 2. `time.after` is generic, `( T i32 -- chan T )`, written in Whackford in the prelude and made only on first use like the channel words, so programs that do not use it get no GC types from it (a concrete `( i32 -- chan i32 )` would put its types in every module); it is unbuffered: the timer process lingers parked on its send if the other `alt` arm won; no buffering, no cancelling, no `time.now` word (`/dev/time` already exists). 3. Sleeping is never blocked. 4. The driver waits for sleepers only while process 0 runs; after it returns they are dropped (`run`, `test`) or stay (REPL). 5.
