Repo: /home/matt/Git/Whackford. crates/runtime/src/proc.rs is the native process scheduler (a state machine; its twin is web/proc.js, which a later task changes to match, so keep names parallel). Add timers: (1) a clock field `now: Box<dyn Fn() -> i64>` giving milliseconds; `Scheduler::new()` uses a real clock (capture `std::time::Instant::now()` at construction and return `elapsed().as_millis() as i64`); add `pub fn with_clock(now: Box<dyn Fn() -> i64>) -> Scheduler` for deterministic tests. (2) `WaitKind::Sleep`, and a field `sleepers: Vec<(i64, Pid)>` (deadline, pid) kept in the order processes slept. (3) In `submit`, before the channel lookup, handle `L::OP_SLEEP`: deadline = now() + a0.max(0) as i64; push onto `sleepers`; `self.park(pid, WaitKind::Sleep, vec![])`. (4) In `next()`: ready processes first as now; when `ready` is empty, find the sleeper with the smallest deadline (the first in `sleepers` among equals) whose deadline <= now(); if there is one, remove it and `wake(pid, 0)`, then pop from `ready` as before. (5) `pub fn sleep_for(&self) -> Option<i64>`: milliseconds until the earliest deadline, clamped to 0; None when nothing sleeps. (6) `blocked()` returns None when `sleepers` is non-empty (a sleeping process can still run; it is never reported as blocked). (7) `kill` and `exit` remove the pid from `sleepers` (killing a sleeping process removes its deadline; `/prog` listing is unchanged: it lists live pids only, and a sleeper is live). Update the module doc comment to mention timers. Add unit tests in the existing `mod tests` using a shared clock (e.g. `Rc<Cell<i64>>` captured by the closure): (a) `OP_SLEEP` with a0=20 parks; `next()` is None and `sleep_for()` is Some(20) before the deadline; after advancing the clock by 20, `next()` gives `Resume { pid, result: 0, start: false }`; (b) two sleepers of 30 and 10 ms wake in deadline order, and two with equal deadlines wake in the order they slept; (c) `blocked(..)` is None while a process sleeps even when process 0 is parked on `OP_CHAN_RECV`; (d) a killed sleeper is gone: `sleep_for()` None and `next()` None after the clock passes its deadline; (e) a negative count is due at once. Verify: `cargo test -p wack-runtime`. Done when it passes (crates/runtime/src/native.rs still compiles unchanged; routing OP_SLEEP there is the next task).
