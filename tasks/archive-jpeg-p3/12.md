Context: in plain mode (`nosmooth`, every component's method 0) rows.emit (jpeg/rows.wack) first calls upsample.plain for each plane into the upsampled buffer `ups` (plane ci's rows start at ci x rr x width, rr = vmax x 8 rows of width samples; a 2x chroma plane is replicated: output sample x reads source sample x/2 of source row r/vexp, the last odd sample taking the same rule), then for each row r calls `colour.row` with space 1 (YCbCr), which per pixel reads y, cb, cr from ups and does four table lookups (cr-r, cb-b, cr-g, cb-g), a shift and three clamps (`colour.ycc`). With 2x horizontal chroma, pixels 2k and 2k+1 share cb and cr, so half the lookups and the chroma replication (two bounds-checked byte stores and two loads per pixel) are redundant; libjpeg's merged upsampler does exactly this and gives the same bytes (jpeg/upsample.wack's header comment already says so). A plane (`struct plane` in jpeg/upsample.wack) exposes plane.data (bytes), plane.base (the slot of the current MCU row, set at the top of rows.emit by `p p i plane.slot plane.base!`), plane.stride, plane.hexp and plane.vexp; the source row for output row r is at base + (r / vexp) x stride.
