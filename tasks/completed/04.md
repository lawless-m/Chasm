TASK: write tools/mutate.py (Python 3 standard library only; `sys.path.insert(0, dirname(__file__)); import harness`, reusing harness.run, harness.FILES, harness.ROOT, harness.DJPEG; never a second copy of the protocol). Options: `--wack` (default ../target/release/wack), `--jobs N` (default os.cpu_count()), `--minutes M` and/or `--iterations N` (stop at whichever comes first; at least one required), `--seed S` (default int(time.time()); printed on the first line), `--save DIR` (default corpus/regressions), `--work DIR` (default /dev/shm/wack-mutate/<pid> when /dev/shm exists, else ../tmp/mutate/<pid>; removed at exit), `--cpu`, `--memory`, `--timeout` (defaults 30, 1128000000 and 60, passed to harness.run; the wall timeout is twice the CPU budget so CPU exhaustion is classified cpu, not hang). Sources: every regular file under corpus/ except names ending .md or .txt (so fuzz/, the generated mutants and regressions/ are sources too). Each of the N worker threads has its own random.Random(seed * 1000 + k) and its own mutant path <work>/w<k>.jpg; per case it picks a source, applies 1 to 4 operators drawn with replacement from: flip (1-8 bytes XORed with a random non-zero byte), ff and zero (a run of 1-32 bytes set to FF or 00), trunc (cut at a random offset >= 1), dupseg, delseg and swapseg (over the segments from SOI to the first SOS as mkfuzz.segments finds them; skipped when there are too few), seglen (a random segment's length set to 0, 1, 2, 3, FFFF or random), splice (this file cut at a random offset, then the tail of another random source from a random offset), dht (a random DHT's 16 counts replaced by random bytes, or its first count set to 3: over-subscribed), sofdim (height and/or width of the first SOF set from {0, 1, 7, 8, 16, 17, 4882, 16384, 16385, 65535, random}, 4882 x 16384 being just under MAX_PIXELS), chunk (1-64 random bytes overwritten) and ins (1-64 random bytes inserted); picks the mode fancy or nosmooth at random; writes the mutant; calls harness.run with the budget, cap and `out=<work>`; deletes the .pnm and .oracle.pnm it produced; counts the class. On trap, hang, cpu, memory or odd it saves the mutant and its note into --save per the README (deduplicated by SHA-1: an input already saved is counted but not rewritten; `expect:` is left absent for the triage); on mismatch it saves the same way into ../tmp/mutate/mismatch/ (a correctness finding, not a robustness one; the README's note format, class mismatch, plus the harness's diff note). Output: the seed and settings first; every failure as it happens (class, saved path, first stderr line); a status line every 60 seconds (elapsed, cases, cases per second, per-class counts, the slowest case so far by wall time with its mutation summary); and the last line exactly `== {cases} cases in {minutes:.1f} min ({rate:.0f}/s): decoded {d}, refused {r}, mismatch {m}, trap {t}, hang {h}, cpu {c}, memory {me}, odd {o}; failing {f}` where failing = mismatch + trap + hang + cpu + memory + odd; exit status 0 only when failing is 0. Write a docstring in the style of harness.py and mkfuzz.py: usage, the operators, the three acceptable outcomes (decoded byte-exact, refused with a code; a mismatch is a correctness finding), what is saved where, the budget and cap values with one sentence of why each (CPU: 1.6x the worst legal 80-megapixel decode measured in tmp/m8/budget-notes.txt; memory: MEM_BUDGET plus 128 MB of host headroom), the RAM and /dev/shm notes above, and the week-long run the plan asks for (`python3 tools/mutate.py --minutes 10080` in a tmux session).
