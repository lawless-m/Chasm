Context: upsample.h2v2-row ( bytes i32 i32 i32 bytes i32 i32 -- ) (src, cur, other, dw >= 3, dst, doff, width = 2dw-1 or 2dw) is one output row of libjpeg's h2v2_fancy_upsample. Today, for every k in 0..dw it loads the column sum cs = 3*src[cur+k] + src[other+k], then for k > 0 loads the left column sum again (two more bytes.at) and for k < dw-1 the right one (two more), and writes the even output `x = 2k` and the odd `x+1` each behind an `x < width` test: six bounds-checked loads, two stores and four branches per pair. libjpeg computes each column sum once and keeps lastcolsum, thiscolsum, nextcolsum in registers: first column `(this*4 + 8) >> 4` and `(this*3 + next + 7) >> 4`; middle columns `(this*3 + last + 8) >> 4` and `(this*3 + next + 7) >> 4`; last column `(this*3 + last + 8) >> 4` and `(this*4 + 7) >> 4`. The decoder's arithmetic per sample is already exactly that. Since width is 2dw-1 or 2dw, every output of the first and middle columns and the even output of the last column lie inside the width; only the last column's odd output (x = 2dw-1) needs the `x < width` test. On big12 fancy the two chroma planes run this word for 6000 output rows of 2000 columns.
