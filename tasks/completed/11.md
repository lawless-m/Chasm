In /home/matt/Git/Whackford/jpeg-decoder/jpeg/markers.wack add, contract first:

- `markers.app0 ( jpeg i32 i32 -- )`: if the payload is at least 5 bytes and starts `4A 46 49 46 00` (JFIF\0), set jfif to 1; anything else is skipped silently (APP0 is also used by JFXX and others).
- `markers.app14 ( jpeg i32 i32 -- )`: if the payload is at least 12 bytes and starts `41 64 6F 62 65` (Adobe), set adobe to 1 and transform to payload byte 11 (version 2 bytes, flags0 2, flags1 2, then transform); otherwise skip.
- `markers.sof ( jpeg i32 i32 i32 -- )`: marker byte, payload start, payload length (B.2.2). A frame already present is UNSUPPORTED_SOF "second SOF (hierarchical)". Payload shorter than 6 is BAD_SEGMENT_LENGTH. Read P, Y, X, Nf; payload length must equal 6 + 3*Nf else BAD_SEGMENT_LENGTH. Build the `array component` (id, h = byte shifted right 4, v = byte and 15, tq) and the frame with kind = marker byte, then `frame.check`, then `data bytes.len` and `MEM_BUDGET i64` to `frame.check-memory`, then store it as `option.some` in jpeg.frame. frame.check must run before any geometry word (hmax may be 0 in hostile input). The component array is the only allocation and happens after the count check; nothing is allocated after frame.check-memory.
