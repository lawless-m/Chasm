TASK: create jpeg/ppm.wack. `ppm.header ( i32 i32 i32 -- str )`: width, height, ncomp (1 or 3) -> `P5\n<w> <h>\n255\n` or `P6\n<w> <h>\n255\n` exactly as djpeg writes it (8-bit only; 12-bit maxval is M6). `ppm.open ( str i32 i32 i32 -- i32 )`: path (`/file/<absolute path>` natively), width, height, ncomp: opens with host.OWRITE (truncating), writes the header, returns the handle; a negative handle traps with `"cannot open output" trap` and a short header write with `"short write" trap` (plain traps, deliberately not refusals: the output path is the host's business, not the input's; say so in a comment). `ppm.row ( i32 bytes -- )`: writes the whole buffer (one output row of width*ncomp samples) with `bytes.as-str host.write`; a result different from the buffer's length traps `"short write"`. Comment that the caller reuses the row buffer after each call, which bytes.as-str allows because the write completes before the next row is built, and that `ppm.row` is the only consumer of decoded rows today (the row sink; a future encoder is the second).
