TASK, in jpeg/arith.wack: (1) `declare arith.reopen ( arith scan i32 i32 i32 i32 -- )`: the scan, the progressive flag, the offset of the first entropy byte, the restart interval and the MCU total; stores scn (option.some) and prog; for each scan component k: when not prog or (ss = 0 and ah = 0) zero the 64 bytes of DC table td[k] and set lastdc[comps[k]] and dcctx[comps[k]] to 0; when not prog or ss > 0 zero the 256 bytes of AC table ta[k]; then pos = the offset, c = 0, a = 0, ct = -16, marker = 0, restart and togo = the interval, next-rst = 0, mcu = 0, total. (2) `declare arith.end-mcu ( arith -- )`: mcu += 1; when restart > 0: togo -= 1; when togo = 0 and mcu < total: the marker must be at pos after any fill FFs (when marker is already set from a mid-data fetch, pos is at its first FF, so one search serves both cases): no marker there (a non-FF byte, or the end of the data) is `BAD_RESTART "RST marker missing after MCU" mcu refusal-n trap`; a marker other than 0xD0 + next-rst is `BAD_RESTART "RST marker out of sequence, expected" next-rst refusal-n trap`; otherwise pos moves past the marker byte, next-rst = (next-rst + 1) & 7, togo = restart, and process_restart's resets run (the same statistics, lastdc/dcctx and c/a/ct/marker resets as arith.reopen's rules, from the stored scn and prog). (3) `declare arith.end ( arith -- i32 )`: after the last MCU: with marker set, move pos past the marker byte and return the marker; otherwise from pos: the end of the data returns -1 (pos unchanged); an FF run followed by a byte other than 00 is a marker (pos past it, return it); anything else (a data byte, or FF 00) is `BAD_ENTROPY_DATA "extraneous bytes after the scan at offset" pos refusal-n trap`.
