Write /home/matt/Git/Whackford/jpeg-encoder/tools/prep_oracle.c: a stdin-to-stdout harness around libjpeg-turbo 3.2.0's RGB-to-YCbCr conversion (jccolor.c rgb_ycc_convert) and its downsampler (jcsample.c h2v2_downsample, h2v1_downsample, fullsize_downsample, including expand_right_edge), the source of every expected value in jpeg/ccolour.wack's and jpeg/downsample.wack's tests. It links the oracle build's static library /home/matt/Git/Whackford/tmp/dl/ljt-3.2.0/build/libjpeg.a (built -DWITH_SIMD=0, the same code cjpeg runs) and calls the modules through the public setup: `#define JPEG_INTERNALS`, `#include <stdio.h>`, `<stdlib.h>`, `"jinclude.h"`, `"jpeglib.h"` (which then includes jpegint.h); `jpeg_std_error`, `jpeg_create_compress`, `jpeg_mem_dest` (a malloc'd buffer that is never read), `image_width` = W, `image_height` = 16, `input_components` = 3, `in_color_space` = JCS_RGB, `jpeg_set_defaults`, then `comp_info[0].h_samp_factor`/`v_samp_factor` set to the requested HxV (components 1 and 2 stay 1x1, as cjpeg -sample sets them), `jpeg_start_compress(&cinfo, TRUE)`, after which `cinfo.cconvert->color_convert` and `cinfo.downsample->downsample` are the 8-bit methods and `comp_info[c].width_in_blocks` is set; `jpeg_destroy_compress` at the end. Two modes, the arguments on the command line and the numbers on stdin separated by whitespace, every output line being decimal values separated by single spaces with a trailing newline (the format of a Whackford probe that prints bytes with `i32.to-str print`):
- `prep-oracle ycc W` (sampling 2x2, irrelevant here): reads W pixels as R G B, runs color_convert on that one row, prints three lines: the W Y values, the W Cb values, the W Cr values.
- `prep-oracle down W HxV` (H and V 1 or 2): reads max_v_samp_factor (= V) rows of W samples of ONE plane and feeds the same plane as all three input planes, each input row allocated `comp_info[c].width_in_blocks * 8 * max_h_samp_factor / comp_info[c].h_samp_factor` bytes (calloc) because expand_right_edge writes past W; runs `downsample(&cinfo, in, 0, out, 0)` with output rows of `width_in_blocks * 8` bytes; prints component 0's v_samp_factor output rows, then component 1's one row, then component 2's one row (so a 2x2 run prints 4 lines, 2x1 and 1x1 print 3).
