Create /home/matt/Git/Whackford/jpeg-encoder/tools/meta_ref.py: the harness's independent prediction of what clean does with an input's metadata. Module API: `predict(data: bytes, grey) -> (code, orientation, profile)`. The walk: data must start FF D8; from offset 2 read markers (FF fill bytes skipped, then the marker byte); stop at SOS (0xDA) or EOI (0xD9); a marker with no length field (0xD8, 0x01, 0xD0 to 0xD7) or a length under 2 or running past the data makes the file unparsable: return (None, None, None) (the decoder refuses such files first). Every other marker has a big-endian 2-byte length that includes itself; the payload is the bytes after the length field. In file order: the first APP1 (0xE1) whose payload starts b'Exif\0\0' is parsed at once (later Exif APP1 segments are ignored): the TIFF data is the payload after those 6 bytes; it needs at least 8 bytes, starting b'II*\0' (little-endian) or b'MM\0*' (big-endian); the 4-byte IFD0 offset at 4, relative to the TIFF start, treated unsigned; offset + 2 must be within the TIFF data; the 2-byte entry count n at the offset; offset + 2 + 12 n must be within the TIFF data; each 12-byte entry is tag, type, count (4 bytes), value (4 bytes); the first entry with tag 0x0112 must have type 3 and count 1 and its value is the 2-byte field at the start of the value bytes, in the TIFF byte order, which must be 1 to 8; any failure is the refusal BAD_EXIF; no tag 0x0112 means orientation 1; no Exif APP1 means 1; nothing else (next-IFD pointer, other tags, sub-IFDs) is read. Each APP2 (0xE2) whose payload starts b'ICC_PROFILE\0' is a chunk, checked at once: the payload must be at least 14 bytes (12 + sequence number + count) and longer than 14 (data after the header), the count nonzero and equal to every other chunk's, the sequence number 1 to count and not seen before; any failure is BAD_ICC (jdicc.c ignores these; clean refuses). After the walk, when chunks were seen: every sequence number 1 to count present else BAD_ICC; the joined length over 1000000 bytes is LIMIT_ICC (checked before the structure); the joined profile at least 128 bytes, its size field (bytes 0 to 3, big-endian) equal to its length, bytes 36 to 39 b'acsp', the tag count (bytes 128 to 131, which must fit) and every 12-byte tag entry (from 132) within the profile, and each entry's offset + size (unsigned) within the profile, else BAD_ICC. Tag contents are not interpreted. The carry decision: `grey` is True (greyscale output), False (colour output) or None (unknown): the validated profile is carried when its data colour space (bytes 16 to 19) is b'RGB ' with grey False or b'GRAY' with grey True; otherwise it is dropped (profile None, not a refusal); with grey None the validated profile is returned whatever its space. Return (None, orientation, profile-or-None) on success, (code, None, None) on a refusal. Refusal order is the file order of the segment that fails, then the post-walk joined-profile checks, exactly as stated here (clean's meta.walk follows the same order). CLI: `python3 -I tools/meta_ref.py [--grey] [--dump PATH] FILE` prints `META <orientation> <icc-bytes>` (icc-bytes the carried profile's length, or 0) with exit 0, or `REFUSED <CODE>` with exit 1, or `UNPARSABLE` with exit 2; --dump writes the carried profile's bytes to PATH (an empty file when none); without --grey a colour output is assumed.
