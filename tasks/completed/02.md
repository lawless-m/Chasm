Context: M2 decodes 8-bit baseline/extended sequential Huffman JPEGs (SOF0/SOF1, 1 or 3 components, any legal sampling factors, restart intervals) byte-exact against `djpeg -dct int -nosmooth -pnm`. The existing corpus has few sampling factors (mostly 2x2 and 1x1, one 2x1, one 4x1 via 4:1:1 YCCK which is out of scope) and few restart intervals, so a deterministic generated set is needed. Facts checked with this cjpeg (3.2.0): `-sample HxV[,...]` accepts 1x1, 2x1, 1x2, 2x2, 4x1, 1x4, 4x2, 2x4, 3x1, 1x3 and per-component lists such as `2x1,1x2,1x1` and `4x1,1x1,2x1`; it REFUSES 4x4 and 3x3 (`Sampling factors too large for interleaved scan`), so leave those out. `-restart N` is in MCU rows, `-restart NB` in MCUs. `-grayscale` writes one component; with `-grayscale -sample 2x2` the single component has sampling 2x2 (like corpus/wild/imagers/blank_800x280.jpg). `-rgb` writes an Adobe RGB file with component ids R G B. `-quality 1` or `-quality 3` without `-baseline` gives 16-bit quantisation tables and SOF1. Source image: `oracle/libjpeg-turbo-3.2.0/bin/djpeg -pnm corpus/primary/testorig.jpg` is a 227x149 P6 PPM (read it from the subprocess's stdout; a P6 header is three whitespace-separated lines: `P6`, `227 149`, `255`, then width*height*3 bytes).
