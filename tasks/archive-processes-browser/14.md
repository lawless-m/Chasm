Repo: /home/matt/Git/Whackford. Read `web/worker-core.js` (the JSPI `ring_enter`) and `web/proc.js`. M11 decision (Inferno style, `/prog/<pid>/ctl`): processes are killed through the namespace, not a word. Paths under `/prog` are handled by the scheduler, where the processes live, before anything reaches the main thread's `Namespace`: opening `/prog` (or `/prog/`) for reading gives a directory handle whose records (same encoding as `/local`: u32 name length, name bytes, u64 size 0, u8 is-dir 1) list the live pids as decimal names in order; `/prog/<pid>/ctl` opened for writing (mode 1) gives a control handle; writing `kill` (an optional trailing newline allowed) to it calls `scheduler.kill(pid)` and returns the bytes written; any other text returns `E_MALFORMED` (-6); an unknown or finished pid is `E_NOT_FOUND` (-1) at open; reading `ctl` is `E_PERMISSION` (-2); closing returns 0; any other path under `/prog` is `E_NOT_FOUND`. A killed process that is parked never resumes (its pending park promise is rejected with the message `killed`, which the entry wrapper treats as a quiet exit, not a trap); a running process that kills itself exits at that write (reject its own ring_enter the same way). Implement in `web/proc.js` as `progOpen/progRead/progWrite/progClose` on `Scheduler` (handles numbered from 3 in a separate map) so the unit test can cover it, and route from the worker's `ring_enter`.
