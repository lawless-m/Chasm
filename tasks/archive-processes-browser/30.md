Repo: /home/matt/Git/Whackford. M11 is browser-first: processes (spawn, channels, alt) run in the browser REPL via JSPI, and the native hosts refuse programs that use them until a native mechanism is chosen. Decision being implemented: `wack run` and `wack test` refuse such programs at compile time with a new stable diagnostic code `E_PROCESSES_UNSUPPORTED` (codes in `crates/core/src/diag.rs` are a contract: add, never rename). This task adds the core support only. Read `crates/core/src/program.rs` (`compile`, `live_words`, `Compilation`), `crates/core/src/check.rs` `process_ops(c: &Compiled) -> bool` (added by task 09: true when the code has `I32Const(op)` directly before `Call(FN_RING)` with `op >= layout::OP_SPAWN`), and how task 09 pushes `E_WASI_UNSUPPORTED` in `compile`.

Changes: (1) `crates/core/src/diag.rs` `codes`: add `pub const E_PROCESSES_UNSUPPORTED: &str = "E_PROCESSES_UNSUPPORTED";` after `E_WASI_UNSUPPORTED` (if task 09 placed it elsewhere, add it at the end; never rename anything). (2) `Compilation` gains `pub processes: Option<String>` (serde-serialised like the other fields): the name of the first word, in word-id order, whose compiled body `process_ops` reports, preferring user words over library words (two passes: non-library first, then any), among the live words when `live` is `Some` (roots exist) and among every word with a body otherwise. Compute it once in `compile` and make task 09's `E_WASI_UNSUPPORTED` check use it (same word, same scan) so there is one scan. (3) No new diagnostic is pushed by `compile` itself for the non-WASI case: the CLI decides (next task).

Tests in `crates/core/tests/compile.rs`: `processes_names_the_first_offending_word`: `: main ( -- ) [ "hi" println ] spawn ;` compiled with `export: true` gives `processes == Some("main")`; `: main ( -- ) chan.make ( chan i32 ) chan.recv drop ;` gives `Some` of a name starting with `chan.`; a program whose only channel use is in a word `main` never reaches gives `None` with `export: true` but `Some` with `export: false` (no roots: every word counts); `examples/sieve.wack`-style programs give `None`; and `Options::default()` on `: f ( -- ) [ ] spawn ;` gives `Some("f")`. Verify: `cargo test -p wack-core` passes and `cargo build -p wack-core --target wasm32-unknown-unknown` succeeds. Done when both pass. Do not touch the CLI, the runtime or any doc in this task.
