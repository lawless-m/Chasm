Repo: /home/matt/Git/Whackford. Milestone M11 (CSP processes and channels) runs processes in the browser REPL's Web Worker with JSPI: the host import `wack.ring_enter` becomes a `WebAssembly.Suspending` function and each process entry is called through `WebAssembly.promising`, so a parked import suspends only its own process. Node 22 has no JSPI (verified: `WebAssembly.Suspending` is undefined), so this can only be checked in headless Vivaldi via `sh web/test/headless.sh test/<page>.html <TAG>` (the harness waits for the page to `console.log('<TAG> ok')`; see `web/test/structs.html` for the pattern). This task proves the mechanism; it must not invent another design.

Setup: `cargo build -p wack-cli`, `sh web/build.sh` (makes `web/wack_web.wasm`, whose `loadCompiler(...).layout` from `web/compiler.js` gives the ring layout constants), and build the same spike program used by the native spike, `tmp/spike.wack` (create it if missing):
```
struct point  x: i32
: churn ( -- )  200000 [ drop 7 point.new drop ] times ;
: park ( str -- )  0 host.open drop ;
export : a ( -- )  1 point.new :> p  "/park/a1" park churn  "/park/a2" park churn  "a:" print p point.x i32.to-str println ;
export : b ( -- )  2 point.new :> q  "/park/b1" park churn  "/park/b2" park churn  "b:" print q point.x i32.to-str println ;
: main ( -- )  a b ;
```
with `./target/debug/wack build --no-opt -o web/test/spike.wasm tmp/spike.wack` (`*.wasm` is git-ignored). The module imports one function `wack.ring_enter`, exports `memory`, `a`, `b`, `main`; each `host.open` writes one submission entry into the ring in its linear memory (fields and offsets in `layout`: SQ_HEAD, SQ_TAIL, SQ_BASE, SQE_SIZE, SQE_OP/USER/A0/A1/A2, CQ_BASE, CQ_TAIL, CQE_USER/RESULT, OP_OPEN/READ/WRITE/CLOSE) then calls `ring_enter`; `web/ring.js` `serviceRing` shows how the main thread reads entries today.

Write `web/test/jspi.html` (loads the compiler for `layout`, starts `new Worker('jspi-worker.js', { type: 'module' })`, prints and `console.log`s `JSPI ok` or `JSPI FAIL <reason>`) and `web/test/jspi-worker.js`: instantiate `test/spike.wasm` with `wack.ring_enter = new WebAssembly.Suspending(async () => { ... })` which reads the pending submission from the exported memory; for an OPEN whose path starts with `/park/` it stores a resolver under that path and `await`s it; `/dev/cons` open returns handle 3, WRITE appends the bytes to an output string, CLOSE returns 0; then it writes the completion entry, advances SQ_HEAD and CQ_TAIL, and returns. Start `const pa = WebAssembly.promising(exports.a)(); const pb = WebAssembly.promising(exports.b)();`, wait until both `/park/a1` and `/park/b1` resolvers exist, then resolve them in the order b1, a1, b2, a2 (non-LIFO), `await Promise.all([pa, pb])`, and check the output contains `a:1` and `b:2`. Also record what happens when a Suspending import is reached from a plain (non-promising) call, since the REPL's worker will have to route every entry through `promising`.

Verify: `sh web/test/headless.sh test/jspi.html JSPI` prints `JSPI ok`. Record findings in `tmp/spike-jspi.md` (JSPI available in Vivaldi 7.9.3970.60; Suspending/promising usable inside a module Worker on a cross-origin-isolated page; GC refs survive suspension and churn; the non-promising-entry behaviour; any gotchas).
