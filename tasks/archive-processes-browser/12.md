Write `web/proc.js`: the M11 scheduler as a pure state machine with no DOM, no Node APIs and no wasm calls, so it can be unit-tested under node and driven by the JSPI worker later. API: `export class Scheduler { constructor(L) }` with processes (pid 0 is the main process, created by `constructor`; `spawn(slot, closure)` makes pid N in spawn order, state `ready`, and returns the pid), channels (`chanMake()` id from 1 with `senders = 1`; per channel: `senders`, `closed`, a FIFO `queued` of pids whose value sits in the wasm queue, a FIFO `receivers` of parked pids each with its alt arm list), and `submit(pid, op, a0, a1, a2, mem)` returning `{ result }` when the op completes at once or `{ park: true }` when `pid` must wait. Rules: SEND pushes `pid` onto `queued`; if a receiver is parked, pop it and make it ready with result (1, or `2*i+1` for an alt arm i) AND pop the front of `queued` making that sender ready with result 0; otherwise the sender parks (result 0 when later taken); SEND on a closed channel is `E_CLOSED` at once. RECV: if `queued` is non-empty, pop its front sender (make it ready with 0) and return 1; else if closed return 0; else park. CLOSE: `senders -= 1`; below zero is `E_CLOSED` (restore the count); at zero mark closed and wake every parked receiver with 0 (there are none when `queued` is non-empty). SENDER: `senders += 1`. ALT: ids read as little-endian i32s from `mem` at a0, count a1; the first id with a queued value or closed wins at once with `2*i+v`; else the process parks as a receiver of every id with its arm index; when woken by one, it is removed from the others. Unknown ids are `E_BAD_HANDLE`. Also `exit(pid)`, `kill(pid)` (removes the pid from every wait list; a killed sender's entry in `queued` stays so its value is still delivered, but it is never woken; returns false for an unknown or finished pid), `next()` → the next ready `{ pid, result }` in FIFO order or null, `ioStart(pid)`/`ioDone(pid)` to mark a process waiting on host I/O, `live()` → pids not finished, and `blocked()` → null while some process is ready or waiting on I/O, else the message `all processes blocked: <name> waits to receive on chan 1; <name> waits to send on chan 1; <name> waits on chan 1, chan 2 (alt)` with names from a `name(pid)` callback (pid 0's name is given by the host, others are `process N`).
