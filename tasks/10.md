In /home/matt/Git/Whackford/jpeg-decoder/jpeg/markers.wack add, contract first, three parsers taking the jpeg, the payload start and the payload length as `markers.segment` returns them:

- `markers.dqt ( jpeg i32 i32 -- )` (T.81 B.2.4.1): loop while bytes remain in the payload: byte Pq/Tq; Pq above 1 is BAD_TABLE; Tq above 3 is BAD_TABLE; the table needs 64 entries of 1 (Pq 0) or 2 (Pq 1, big-endian) bytes and a payload too short for them is BAD_SEGMENT_LENGTH; store the 64 values at qt[Tq*64+k] in the order read and set qt-set[Tq] to 1. An empty payload, or a payload not consumed exactly, is BAD_SEGMENT_LENGTH. The loop is bounded by the payload length.
- `markers.dht ( jpeg i32 i32 -- )` (B.2.4.2): loop while bytes remain: byte Tc/Th; Tc above 1 is BAD_TABLE; Th above 3 is BAD_TABLE; 16 counts must follow (BAD_SEGMENT_LENGTH); total = sum of counts, above 256 is BAD_TABLE; total symbol bytes must follow (BAD_SEGMENT_LENGTH); over-subscription: the sum over len 1..16 of counts[len] shifted left by (16-len) must not exceed 65536, else BAD_TABLE (Kraft; fits i32); set huff-at[Tc*4+Th] to the offset of the counts; advance 17+total. Payload not consumed exactly is BAD_SEGMENT_LENGTH. Symbols are not stored in M0 (M1 reads them from huff-at).
- `markers.dri ( jpeg i32 i32 -- )`: payload length must be 2 (BAD_SEGMENT_LENGTH); stores the u16 in restart.
