## synthetic/

Generated from libjpeg-turbo 2.1.5's `testimages/testorig.ppm` (227x149):

- `cmyk-pillow-*`: Pillow 11.1.0, CMYK with Adobe transform 0 (`tools/gen_cmyk.py`)
- `ycck-tj-*`: TurboJPEG 2.1.5 via ctypes, a CMYK buffer compressed to YCCK (Adobe transform 2), at 4:4:4, 4:2:2, 4:2:0, 4:4:0 and 4:1:1 (`tools/gen_cmyk.py`)
- `ycck-magick-*`: ImageMagick `magick in.ppm -colorspace CMYK -quality 90 out.jpg` (and `-sampling-factor 2x2 -quality 75`), which writes YCCK, not plain CMYK

Rebuild: `python3 -I tools/gen_cmyk.py <testorig.ppm> corpus/synthetic`, then the two `magick` commands.
- `p12-*`: 12-bit, cjpeg 3.2.0 `-precision 12 -quality 90` from djpeg 3.2.0's 12-bit decode of `primary/testorig12.jpg` (P6, maxval 4095): `seq-420`, `seq-444` (`-sample 1x1`), `seq-422-rst2` (`-sample 2x1 -restart 2`), `grey` (`-grayscale`), `prog-420` (`-progressive`), `arith-420` (`-arithmetic`), `arith-prog-420` (`-arithmetic -progressive`)
- `lossless12-psv1`, `lossless8-psv1`: cjpeg 3.2.0 `-lossless 1` (SOF3), to be refused `UNSUPPORTED_SOF`

## The oracle

`oracle/libjpeg-turbo-3.2.0/`: libjpeg-turbo tag 3.2.0 (c85e6b905bf237038faa936dab160ebfc5da0344), built with
`cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DWITH_SIMD=0 -DENABLE_SHARED=0 -DCMAKE_INSTALL_PREFIX=<that dir>`, then `ninja install`.
Its `bin/djpeg` decodes 12-bit (PPM maxval 4095) and lossless, and writes CMYK/YCCK to PPM as RGB by
`cmyk_to_rgb` in `src/cmyk.h`: `r = c*k/maxval + 0.5`, which is `(2*c*k + maxval) / (2*maxval)` in integers.
The system djpeg (2.1.5) does neither 12-bit nor lossless; do not use it as the oracle.

## synthetic-m2/

73 baseline files generated by `python3 -I tools/gen_m2.py` with cjpeg 3.2.0
(the oracle build) from `primary/testorig.jpg`, decoded by the oracle's djpeg
and recompressed: every sampling factor cjpeg accepts (1x1 to 4x2, 3x1, 1x3,
and per-component lists), crops from 1x1 to 64x48 in colour 2x2, 1x1, 2x1
and greyscale, restart intervals in MCU rows and in MCUs, greyscale with 2x2
sampling, `-rgb`, `-quality 100`, `-quality 1` and `3` (16-bit tables, SOF1)
and `-optimize`. The script checks that every file decodes with
`djpeg -dct int -nosmooth -pnm` with exit status 0 and nothing on stderr;
rerunning it writes identical files.

## synthetic-m3/

93 files generated by `python3 -I tools/gen_m3.py` with cjpeg 3.2.0 (the
oracle build, `-dct int -optimize -sample S`) from `primary/testorig.jpg`:
14 crops from 3x3 to 33x34 taken at offset (100, 60), each with six
samplings (2x2, 2x1, 1x2 and three per-component lists); the full image with
eight per-component lists; and a 16x18 4:2:0 crop with a restart marker
every MCU row. They cover the fancy-upsampling edges: the downsampled-width
rule for h2v1 and h2v2, partial last MCU rows, the context across MCU rows,
and h1v2 beside h2v2. The script checks that every file decodes with both
`djpeg -dct int -pnm` and `djpeg -dct int -nosmooth -pnm`, exit status 0 and
nothing on stderr; rerunning it writes identical files.

## synthetic-m4/

83 progressive and multi-scan files generated by `python3 -I tools/gen_m4.py`
with cjpeg 3.2.0 (the oracle build, `-dct int`) from `primary/testorig.jpg`
(crops at offset (100, 60)) and from two flat images: libjpeg's standard
progressive script on seven samplings and crops from 1x1 to 64x48; the same
with restart intervals; scan scripts for DC only, DC in two steps, AC left
at Al 2 and 1, spectral bands, coefficients never sent, successive
approximation to depth 3 and separate DC scans per component, in colour and
greyscale; flat images with long EOB runs; and multi-scan sequential files
(one scan per component, reversed order, restarts, SOF1 and `-optimize`).
The script checks that every file decodes with both `djpeg -dct int -pnm`
and `djpeg -dct int -nosmooth -pnm`, exit status 0 and nothing on stderr;
rerunning it writes identical files.

## synthetic-m5/

1035 arithmetic-coded files generated by `python3 -I tools/gen_m5.py` with
jpegtran and cjpeg 3.2.0 (the oracle build). 952 are `jpegtran -arithmetic`
twins of every file in `tools/m2-decoded.txt`, `synthetic-m2/` and
`synthetic-m3/`, in four variants: sequential (SOF9), progressive (SOF10,
libjpeg's standard ten scans), sequential with a restart every MCU row, and
progressive with a restart every four MCUs. A twin keeps its original's
quantised coefficients, so it must decode to exactly the original's pixels.
The other 83 rerun `tools/gen_m4.py`'s cjpeg invocations with `-arithmetic`
added (scan scripts, smoothing cases, greyscale, samplings, flat images,
16-bit tables) and must decode as their `synthetic-m4/` counterparts do. The
script checks every file in both `djpeg -dct int -pnm` and `djpeg -dct int
-nosmooth -pnm` against that reference, exit status 0 and nothing on
stderr; rerunning it writes identical files.

## synthetic-m6/

162 12-bit files generated by `python3 -I tools/gen_m6.py` with cjpeg and
jpegtran 3.2.0 (the oracle build), `-precision 12 -dct int`, from djpeg's
12-bit decode of `primary/testorig12.jpg` (crops at offset (100, 60)) and
two flat maxval-4095 images: extended sequential Huffman over every
sampling and crops from 1x1 to 64x48; restarts; quality 1, 3 and 100
(16-bit tables, large coefficients); progressive with libjpeg's standard
script, with restarts and with the scan scripts of `tools/gen_m4.py`
(smoothing cases, deep successive approximation, multi-scan sequential);
arithmetic sequential and progressive; and 32 jpegtran twins (arithmetic,
progressive, restarts) of the eight 12-bit originals, each identical in
output to its original. The script checks every file in both `djpeg -dct int
-pnm` and `djpeg -dct int -nosmooth -pnm`, exit status 0 and nothing on
stderr; rerunning it writes identical files.

## synthetic-m7/

143 four-component and header-variant files generated by `python3 -I
tools/gen_m7.py`: 39 Pillow 11.1.0 CMYK files (Adobe transform 0, K
unsampled) of djpeg's decode of `primary/testorig.jpg` over samplings,
crops from 1x1 to 64x48, qualities, Huffman optimisation, progressive and
restarts; 24 YCCK files (Adobe transform 2, K sampled like Y) from the
oracle's tjbench over every subsampling it writes, progressive, arithmetic
and restarts; 16 12-bit YCCK files and CMYK copies (transform byte, file
offset 17, set to 0) from djpeg's 12-bit decode of `primary/testorig12.jpg`;
52 jpegtran twins (arithmetic, progressive, restarts) of the thirteen
4-component corpus originals, each identical in output to its original; and
12 header variants that pin libjpeg-turbo's colour-space rules (Adobe
marker removed or JFIF added on CMYK, YCCK and RGB files; testorig without
JFIF, with Adobe transform 1, with component ids R G B and 0 1 2). djpeg
writes CMYK and YCCK images as RGB through cmyk.h's cmyk_to_rgb (each
channel times K over the maximum sample, rounded); neither libjpeg-turbo
nor djpeg applies any Adobe or Photoshop inversion (neither does invert
CMYK), and the decoder follows
djpeg with the integer form (2 c k + maxval) / (2 maxval), so the plan's
inversion and raw-plane comparison are superseded. The `ycck-tj-*` files in
`synthetic/` decode to all-black output (K is 0 everywhere), so they test
the entropy and sample paths but not the colour conversion; the YCCK header
variants start from `synthetic/ycck-magick-q90-444.jpg`. The script checks
every file in both `djpeg -dct int -pnm` and `djpeg -dct int -nosmooth
-pnm`, exit status 0 and nothing on stderr; rerunning it writes identical
files.

## regressions/

Every input that ever made the decoder trap, hang, exceed the harness's CPU
budget or hit its memory cap, saved by `tools/mutate.py` with a `.txt` note
beside it whose `expect:` line says how the fixed decoder treats it. The
gate requires every file to match its note in both upsampling modes;
`regressions/README.md` has the naming and the note format.
